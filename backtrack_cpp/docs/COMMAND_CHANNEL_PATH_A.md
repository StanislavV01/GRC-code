# Командний канал — Варіант A: CM4 → MAVLink-over-CAN → GUIDED

Обрано 2026-08-10. Мета: наш backtrack-мозок на CM4 керує НРК, віддаючи автопілоту
**швидкість (GUIDED) по MAVLink**, а MAVLink іде **через DroneCAN serial-тунель по
наявному CAN1**. Автопілот лишається ЄДИНИМ майстром моторів → безпечно (усі його
arming/failsafe/ліміти працюють; жодних двох майстрів на ESC).

```
[backtrack C++ мозок] → (v, omega) → [MAVLink GUIDED] → mavlink2rest(BlueOS)
   → DroneCAN serial tunnel (CAN1) → [ArduPilot Rover node 10] → ESC → гусениці
```

## Частина 1 — ArduPilot (робить КОМАНДА; я параметри не міняю)

Зараз `CAN_D1_UC_SER_EN=0` (тунель off) і BlueOS не бачить автопілота (mavlink2rest
порожній). Треба:

1. **Увімкнути DroneCAN serial-тунель:** `CAN_D1_UC_SER_EN = 1` (на CAN1).
2. **Вивести MAVLink у тунель:** призначити один `SERIALx_PROTOCOL = 2` (MAVLink2)
   на порт, який ArduPilot тунелює по DroneCAN (за докою ArduPilot «DroneCAN serial
   tunnelling»; точний мапінг SERIALx↔тунель звірити з версією прошивки). Baud за
   докою.
3. **GUIDED готовність:** переконатись, що доступний режим GUIDED для Rover; при
   потребі — окремий канал/скрипт перемикання режиму. `ARMING_CHECK` наразі `0`
   (перевірки вимкнені) — для тесту це спрощує arm, але зважити на безпеку.
4. **Failsafe не має заважати нам:** `FS_GCS_TIMEOUT=5 c`, `FS_ACTION=2 (Hold)`.
   Наш CM4 має слати HEARTBEAT у тунель, інакше GCS-failsafe спрацює на нас під час
   backtrack. (Пізніше можна зав'язати трігер backtrack саме на цей failsafe.)

**Критерій успіху Частини 1:** у `http://<pi>:6040/mavlink/vehicles/1/...` з'явиться
**HEARTBEAT від sysid 1** (автопілот) — зараз його немає. Це підтвердить, що канал
живий. Тоді переходимо до коду.

## Частина 2 — BlueOS

Переконатись, що MAVLink із тунелю доходить до mavlink-router/mavlink2rest BlueOS
(додати endpoint, якщо тунель презентується як serial/UDP). Ознака — той самий
HEARTBEAT у mavlink2rest.

## Частина 3 — наш бік (CM4), пишу ПІСЛЯ підняття каналу

Новий вихідний шлях (окремо від listen-only одометрії):
- **Транспорт:** слати MAVLink через **mavlink2rest** (HTTP POST месиджів) — не
  треба свого DroneCAN-тунель-клієнта, BlueOS уже маршрутизує.
- **Потік GUIDED:**
  1. `HEARTBEAT` від CM4 ~1 Гц (щоб не тригерити GCS-failsafe автопілота).
  2. Перемкнути режим у **GUIDED** (`SET_MODE` / `MAV_CMD_DO_SET_MODE`).
  3. `ARM` (`MAV_CMD_COMPONENT_ARM_DISARM`) — тільки в тесті, з дозволу.
  4. Стрім швидкості ~5–10 Гц: `SET_POSITION_TARGET_LOCAL_NED` з type_mask на
     **velocity** (vx, і yaw_rate для повороту) у BODY-frame. Backtrack дає (v, ω).
  5. На прибуття / стоп — нульова швидкість, вихід із GUIDED або DISARM.
- **Структурно:** ввести інтерфейс `IGuidedSink` (send_velocity, arm, set_mode,
  heartbeat); реалізація `Mavlink2RestSink`. Backtrack-контролер → IGuidedSink.
  Це вкручується в новий застосунок (напр. `run_vehicle_guided`) або як командний
  режим `run_observe` (замість no-op set_erpm).

## Частина 4 — Безпека (жорстко)

- **Dry-run за замовчуванням:** без явного прапорця `--go` код лише ЛОГУЄ месиджі,
  нічого не POST-ить.
- **Ліміти:** `--max-speed` малий (напр. 0.3 м/с), `--max-yaw`, `--max-seconds`
  (авто-стоп), watchdog: нема свіжої пози/одометрії → нульова швидкість.
- **Перший рух — на стенді:** колеса від землі, оператор з рукою на вимкненні
  живлення, хтось страхує. Крихітний газ, коротко, перевірити напрям/боки.
- **Тільки з явним дозволом** слати в CAN. Listen-only одометрія лишається окремо.

## Частина 5 — Процедура першого тесту (коли канал є)

1. Підтвердити HEARTBEAT автопілота в mavlink2rest (Частина 1).
2. Я пишу `Mavlink2RestSink` + командний режим, ганяю **dry-run** (лог месиджів,
   нічого не шлю) — звірити, що GUIDED-потік коректний.
3. На стенді, з дозволу: `--go --max-speed 0.3 --max-seconds 5`. Тригер backtrack
   → дивимось, чи гусениці крутяться в правильний бік із малим газом; авто-стоп.
4. Нарощуємо обережно; далі — на землі з геозоною.
